## 1. How the app works (three parts)
| Part | Where it runs | What it does | Can GitHub do it? |
|---|---|---|---|
| **The page** (`index.html`) | GitHub Pages (free) | Everything you see; saves your bets in your browser | Yes |
| **The Worker** (a small server) | Cloudflare Workers (free plan) | Holds the API keys as secrets, calls the APIs for the page, saves answers for a few minutes so calls aren't wasted | Not GitHub Pages, but you can deploy it **from** GitHub with no Mac (section 3) |
| **ESPN** | ESPN's public site | Scores, schedules, grading | No key needed; the page calls it directly |

**Why the Worker matters.**
- GitHub Pages only serves files, and anyone can read those files.
- Put an API key in the page, or in a public repo, and anyone can copy it and spend your credits.
- The Worker keeps the keys hidden. The page only knows the Worker's address, plus a passphrase so strangers can't use it.

## 2. The APIs, in detail
Each one needs its own account and key, except ESPN. **Use your own keys, never Alonzo's.** Free limits change, so check each site.

| API | What it gives | How a call is made | Cost / free limit | Notes |
|---|---|---|---|---|
| **ESPN** (public) | Scores, schedules, live stats, rosters, headshots | `https://site.api.espn.com/apis/site/v2/sports/{sport}/{league}/scoreboard?dates=YYYYMMDD` (e.g. `soccer/esp.1` is La Liga, `basketball/nba`) | Free, no key | Unofficial, so it can change without notice. Grading uses it |
| **The Odds API** | Moneyline, spreads, totals from many books, Pinnacle included (region `eu`); DFS lines (`us_dfs`); exchanges (`us_ex`) | `https://api.the-odds-api.com/v4/sports?apiKey=KEY` lists leagues. `/v4/sports/{key}/events` lists games. `/v4/sports/{key}/odds?regions=us&markets=h2h,spreads,totals` gives odds | 500 free credits a month. Odds cost markets × regions per call. Several sources say the league and game lists are free | Response headers `x-requests-remaining` and `x-requests-used` show your balance. The easiest place to start |
| **BettingPros** | Player props, projections, cover %, consensus, game lines | API key in the request header (from their developer access) | Alonzo's plan: 50 calls a day | The main board. Props come 20 per call |
| **SportsGameOdds** | Props and game lines from FanDuel, DraftKings, BetMGM, Caesars, ESPN Bet, Bovada, others, with their own no-vig "fair odds" | Key in a header; events endpoint, filtered by league | Free plan: 2,500 games a month; some leagues (EPL, La Liga) need a paid tier | Good for props when BettingPros is out of calls |
| **Sportsbook API** | Its own +EV picks, with each market's average price | Key in a header; one call returns the picks | About 150 calls a day on Alonzo's plan | The screener re-checks every pick (fees, caps) |
| **OddsPapi** | Pinnacle no-vig prices next to other books | Key; one call per game | Monthly allowance | Alonzo uses it for NFL totals |
| **Kalshi, Polymarket US, Novig** | Your own fills and settlements; live exchange prices | Each exchange's account API, read-only keys | Free with an account | Personal. Only your own account's keys |

**How the screener decides a bet is worth it.**
1. Take the sharp price, Pinnacle's or the market average. Remove the vig: each side's chance divided by the total of all sides. That gives the **fair chance**.
2. Compare it to the price on a book you can bet: `EV = fair chance ÷ book's implied chance − 1`, minus fees.
3. Only bet when EV clears a floor. Stake with a fraction of Kelly, capped per bet, per game and per day.

## 3. Why ChatGPT could not finish the setup, and the fix
**GitHub cannot run a Worker.**
- GitHub Pages only serves files. It cannot keep a key secret or call an API for the page.
- Some APIs also refuse calls straight from a web page (CORS).
- So a GitHub-only setup either breaks, or exposes the key. That is most likely where ChatGPT got stuck.

**The fix:** the page stays on GitHub, and a small Worker runs on Cloudflare (free). Cloudflare deploys it straight from your GitHub repo, so no Mac or Terminal is needed. **Augi uses his own keys. Nothing of Alonzo's is shared.**

### Step by step (all in the browser, about 20 minutes)
1. **A private repo for the Worker.**
   - On GitHub: New repository → name `my-odds-worker` → **Private** → Create.
   - Add the two files below (Add file → Create new file).
2. **Connect it to Cloudflare.**
   - Make a free Cloudflare account. Go to Workers & Pages → Create → **Import a repository**.
   - Connect GitHub, pick `my-odds-worker`, then Deploy.
   - From then on, every change you commit on GitHub deploys by itself.
3. **Add the secrets, never in a file.** In the Worker, go to Settings → Variables and Secrets → Add, type **Secret**:
   - `ODDS_API_KEY`: your The Odds API key.
   - `PASS`: a long passphrase that you make up.
   - Add one per API later (for example `BP_KEY`).
4. **Your Worker's address** looks like `https://my-odds-worker.<your-name>.workers.dev`. Your page calls it, sending the passphrase in a header named `x-pass`.
5. **Test it** from your page: ask ChatGPT for a small `fetch` that calls `/odds/sports` with the `x-pass` header. Opening the address in a browser tab answers `locked`, and that is correct.

### File 1: `wrangler.toml`
```toml
name = "my-odds-worker"
main = "worker.js"
compatibility_date = "2024-09-01"
```

### File 2: `worker.js` (a starter: The Odds API only; add each other API the same way)
```js
// Keys live in Cloudflare secrets (env.ODDS_API_KEY, env.PASS), never in this file.
const OA = 'https://api.the-odds-api.com/v4';
const ok = s => /^[a-z0-9_,]{1,80}$/.test(s || '');           // only plain keys pass through
export default {
  async fetch(req, env, ctx) {
    const cors = { 'access-control-allow-origin': '*', 'access-control-allow-headers': 'x-pass',
                   'access-control-expose-headers': 'x-requests-remaining, x-requests-used' };
    if (req.method === 'OPTIONS') return new Response(null, { headers: cors });
    if (!env.PASS || req.headers.get('x-pass') !== env.PASS) return new Response('locked', { status: 401, headers: cors });
    const u = new URL(req.url), q = u.searchParams, key = 'apiKey=' + env.ODDS_API_KEY;
    let target = null;
    if (u.pathname === '/odds/sports') target = `${OA}/sports?${key}`;                                   // free: every league in season
    else if (u.pathname === '/odds/events' && ok(q.get('sport'))) target = `${OA}/sports/${q.get('sport')}/events?${key}`;   // free: the games
    else if (u.pathname === '/odds' && ok(q.get('sport'))) {                                              // costs credits: markets x regions
      const regions = ok(q.get('regions')) ? q.get('regions') : 'us', markets = ok(q.get('markets')) ? q.get('markets') : 'h2h';
      target = `${OA}/sports/${q.get('sport')}/odds?regions=${regions}&markets=${markets}&oddsFormat=american&${key}`;
    }
    if (!target) return new Response('unknown route', { status: 404, headers: cors });
    const cache = caches.default, ck = new Request(u.toString());                 // the same question within 10 minutes costs nothing
    let res = await cache.match(ck);
    if (!res) {
      const up = await fetch(target);
      res = new Response(up.body, up); res.headers.set('cache-control', 'max-age=600');
      if (up.ok) ctx.waitUntil(cache.put(ck, res.clone()));
    }
    const out = new Response(res.body, res); Object.entries(cors).forEach(([k, v]) => out.headers.set(k, v));
    return out;
  }
};
```
**To add another API** (BettingPros, SportsGameOdds and others):
- Add a route the same way, with that API's address and key, as its docs describe.
- Put its key in a new secret.
- Tell ChatGPT: "add a route `/bp` to my Worker that calls <the address from the docs> with the key from `env.BP_KEY` in the header their docs name". Don't paste the key itself.

### Security
- Keep the Worker repo **private**. Never paste keys or the passphrase into ChatGPT or any chat. If one leaks, change it in the provider's dashboard and in the Worker's secrets.
- Cloudflare can also limit how often one visitor calls the Worker (Security → WAF → Rate limiting rules). That stops someone from guessing the passphrase.

**Why it works for you on campus Wi-Fi and not for Alonzo.**
- When ChatGPT or GitHub's servers fetch BettingPros, your network only sees chatgpt.com or github.com.
- Alonzo's browser has to reach 0xbeta.dev, which the campus blocks.
- A `github.io` address and a Cloudflare `workers.dev` address may also get blocked. Don't try to get around a school's filter; use cell data.

## 4. Working with ChatGPT the same way Alonzo works with Claude
1. **One build, one place:** your GitHub repo. ChatGPT writes or changes code, you paste it into GitHub, and the page republishes in about a minute.
2. **One change at a time.** Ask for the exact lines to change, not a whole new file. A whole file can silently drop features.
3. **Test before you publish.** Keep a second branch, or test on your phone with the page's saved board, before merging to `main`.
4. **Notes with versions.** Keep a folder like `agent-notes/`, with one file per step: `<topic>_<date>_v<N>.md`, a Ref number, and what changed. Paste the newest note into ChatGPT at the start of each chat so it remembers.
5. **A second opinion.** Paste a change into a different AI (or Claude) and ask it to look for bugs before betting real money.

## 5. Gotchas from building this one
- Much of the page's HTML sits inside JavaScript strings in single quotes. An apostrophe ("it's") breaks the whole app; write "it is".
- Team codes differ between sources (NYK vs NY). Normalise them before matching games.
- Soccer moneylines have three outcomes (home, draw, away). Remove the vig over all three, or the fair price is wrong.
- Grade from ESPN's final score, and soccer on regular time only. A league ESPN doesn't cover needs grading by hand.
