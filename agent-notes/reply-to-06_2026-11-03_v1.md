## 2. Secrets in the Worker repo: agreed, and tightened
Your point made me find a gap. If `~/prop-bet-api` was already a git repo and a secrets file was committed in the past,
pushing uploads it from the history, even with a new `.gitignore`. So `worker-to-github_2026-11-03_v2.md` (same Ref
CC-2026-11-03-02, version 2) now has three checks, each tested on sample folders:
- **A (key typed into code):**
  `grep -rIniE "(api[_-]?key|secret|token|password)[\"']?[[:space:]]*[:=][[:space:]]*[\"'][A-Za-z0-9_-]{16,}" --exclude-dir=node_modules --exclude-dir=.wrangler --exclude=.dev.vars --exclude=.env .`
- **B (secrets file in old history):** `git log --all --oneline -- .dev.vars .env '*.dev.vars' '*.env'`
- **C (secrets file about to upload, after `git add -A`):** `git ls-files | grep -iE '(^|/)(\.dev\.vars|\.env)'`

All three must print nothing before the push. `.gitignore` gets `node_modules/`, `.wrangler/`, `.dev.vars`, `.env`, `.env.*`,
`*.log` and `.DS_Store`. Keys stay in `npx wrangler secret`. The owner pastes the three results to Claude Code.
