## 2. Worker calls: Novig lines travel together (v4.25)

Since v3.16 every Novig moneyline, spread or total went to the Worker as its own `/live` request, because one Worker request may make 45 outside
calls and finding a Novig game line on an NFL Sunday can take 14 catalogue pages. But the Worker reads a page once per request however many bets
need it, and both sides of a game share one order-book read. So:

| What | v4.24 | v4.25 |
|---|---|---|
| Novig game lines in one `/live` request | 1 | up to 6, grouped by league and kickoff (3 games, both sides) |
| A Live edges scan, 30 games, Kalshi + Novig | about 80 requests | about 20 (one call per 3 games, both teams, every exchange you bet) |
| A failed or "busy" exchange answer | kept 3 minutes | asked again after 1 minute (a good one is still kept 3 while ESPN is unchanged) |
| The Sentinels, the board swap, your bets' live prices | one request per Novig game line | the same grouping (they all go through the same wrapper) |

On a cold cache a group of 6 costs the Worker about 36 of its 45 calls; the 7th and later lines go in the next request. If a request still runs
out, the extra lines come back "busy" and are asked again a minute later, so nothing is lost.

Polling already ran only in the tab you are looking at (fills, orders, live prices, live edges, sync all check `visibilityState`); the new test
proves a hidden page makes no Worker calls for 5 minutes and resumes within a minute of coming back.

## 4. The CHI bet: "it should say that I already made a bet"

What happened: Novig filled "CHI Winner" ($1.23 to pay $5.72, PHI @ CHI 2:35 PM) at 11:07 AM. The Worker describes that fill as team CHI,
moneyline, kickoff 2:35 PM, but Novig gives no game with it, so the app logged it as "CHI · Moneyline" with no game text. The Sentinels card
said "Chicago Bulls · Moneyline · Philadelphia @ Chicago · Novig +388". The two already-bet matches both missed: the name match ("CHI" is not
"Chicago Bulls") and the game match (the logged bet had no game). The third match, by Novig market id, only works when the card's price came
from that same market; this card's price did, but the log entry is what was missing, so there was no id to compare with.

What changed (v4.25): a game line with the same kind and team code (ESPN's code for a long name), on the same game day or within 6 hours, is
your bet, whatever the price (a spread needs the same line too). The card goes to Already bet with "ALREADY BET at +365", no stake, no I bet
this. The name and game matches now also require the same game time, so a bet on CHI today no longer marks CHI's game tomorrow. The 76ers in
the same game get the "OTHER side of your CHI Moneyline" warning. `tests/fill-prior-test.js` is your case; it fails on v4.24 and passes now.

Please check one thing on your phone: the Bet log should have the CHI bet (logged on its own from the Novig fill, "by Novig"). If it is not
there and the fill sits under From your books as "Novig market 2c91fd9d…" with no description, the Worker could not name the market: Novig
names a market only while it is open, and its API answers 451 when the app's location check is stale (opening the Novig app fixes that).

gets its game text and grades against the exact game. 4 unit checks; the deploy workflow's route test still passes. **Publish Worker v3.42 now?**
